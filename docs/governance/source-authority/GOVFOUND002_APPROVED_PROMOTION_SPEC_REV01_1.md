17. Conflict-Resolution Rules

17.1 Business Bible versus Domain Owner

Business Bible controls cross-domain doctrine.

Domain Owner controls detailed domain policy.

Domain policy may refine but not silently contradict doctrine.

Conflict requires governance reconciliation.

17.2 Domain Owner versus Runtime Contract

Domain Owner controls the required policy outcome.

Runtime Contract controls enforceable system behavior.

Runtime Contract may add implementation precision.

Runtime Contract may not weaken or contradict domain policy.

Conflict requires correction or formal policy reconsideration.

17.3 Runtime Contract versus Implementation

Runtime Contract controls.

Implementation defects do not redefine the contract.

Implementation must be corrected unless the contract is separately changed through governance.

17.4 Implementation versus Observed Runtime

Observed Runtime establishes what happened.

Implementation artifacts establish what was intended or deployed.

A difference indicates drift, defect, manual intervention, environmental behavior, customer modification, or incomplete evidence.

Observed Runtime does not silently amend implementation authority.

17.5 Approved source versus MTR

If Contract ID, fingerprint, scope, boundaries, or totals disagree, execution stops.

The MTR may reference or summarize the contract but may not revise it.

17.6 Approved source versus Work Order

If the Work Order differs materially from this approved source, execution stops.

The Work Order may add bounded execution detail but may not change the approved contract.

17.7 Approved source versus repository copy

Before merge, this approved source remains the approval authority and the repository copy is the validation target.

A material mismatch must be corrected faithfully within the approved contract or execution must stop.

17.8 Evidence versus Authority

Evidence records reality and history.

Authority defines the active rule.

Repeated unauthorized behavior does not become authorized through repetition.

17.9 Same-level conflict

When two artifacts appear to own the same subject:

inspect authority boundaries;

inspect document status and revision;

inspect predecessor and successor relationships;

determine the active owner;

record unresolved ambiguity;

stop affected work if ownership cannot be resolved;

require a separately authorized reconciliation task when correction is needed.
